# Feature Roadmap

## Completed
- [x] **Per-Instance Distribution** — distribution now connects directly to dedicated per-profile Anki instances (`DISTRIBUTION_TARGETS` = `Name=URL` pairs) instead of switching profiles on one instance. Receivers are auto-provisioned (notetype from source definition + deck). Profile-switching machinery removed entirely (ProfileLock, loadProfileAndWait, ACTIVE_PROFILE, DISTRIBUTION_PROFILES, /api/anki/profiles, ProfileIndicator, settings ProfilesSection). Delete propagation removed — deletes act on the source instance only (libraries are not guaranteed mirrors; a future explicit "retire word everywhere" action is a separate feature). New `src/lib/distribution.ts` + `createAnkiClient(url)` factory. 81 Vitest + 1 Playwright + 1 real-container integration test (`npm run test:integration`, 8770→8771). Spec: `docs/superpowers/specs/2026-07-04-per-instance-distribution-design.md`, plan: `docs/superpowers/plans/2026-07-04-per-instance-distribution.md`.
- [x] **2026-07-03 Bugfix bundle: deck placement guard / CLI model pin / image-gen retry** — (1) addNote/addNotes verify new cards landed in the requested deck and changeDeck misplaced ones back (root cause: dangling notetype `did` + AnkiConnect in-memory deck passing → cards intermittently fell into "Default"); (2) Claude CLI calls pin `--model claude-opus-4-8` so extraction quality doesn't drift with the environment's CLI default; (3) `generateImage` retries once (1s delay) on transient Gemini failures. Spec: `docs/superpowers/specs/2026-07-03-deck-guard-model-pin-image-retry.md`.
- [x] **Feature 1: Duplicate Detection on Add** — Pre-check words against existing Anki notes before submission. Quick Add shows warning panel; upload flow shows "duplicate" badge.
- [x] **Feature 2: Dashboard "Needs Attention" Section** — Show counts of cards with missing fields on the dashboard. One-click link to enrich them.
- [x] **Feature 5: Auto-Enrich on Add** — After Quick Add, "Enrich N Cards" button navigates to enrich page with autoEnrich=true. Pipeline runs: text batch → save → audio per card → save. Progress banner shows each phase.
- [x] **Batch Audio Generation** — "Generate All Audio (N)" button on enrich page batch-generates word audio (+ sentence audio where available) for all cards missing audio.
- [x] **Batch Image Generation** — "Generate All Images (N)" button on enrich page batch-generates images for all cards that have sentences but no image.
- [x] **Feature 6: Telegram Bot Integration** — Telegram bot via grammy (long-polling) that accepts words or worksheet photos, creates cards, and auto-enriches with text, audio, and images. Runs inside Next.js via instrumentation.ts. Access control via allowed user IDs in Settings.
- [x] **Anki Sync Before Save + Manual Sync** — Auto-sync before all write operations to prevent conflicts across devices. Manual "Sync" button on Dashboard with spinner and success/error feedback.
- [x] **Claude Code Enrichment Skill** — Distributable skill in `skill/` exposing the enrichment API as CLI scripts. Supports text enrichment, audio/image generation, full pipeline, and worksheet extraction. SKILL.md provides intent-to-script mapping for conversational use.

## Recently Completed
- [x] **Fix: Telegram bot misclassified Chinese idiom-containing word lists as sentences** — `"合适，表示，安静，劝告，差不多，后悔，件，手舞足蹈，夜"` was misclassified because the old `hasClauses = commaParts.some(>3 CJK)` heuristic fired on the 4-character chengyu `手舞足蹈`. Replaced the brittle length/comma heuristic in `detectIntent` with an AI classifier (`classifyTextIntent` in `src/lib/ai.ts`), gated by deterministic short-circuits (empty, `/command`, end-punctuation, short single-token) so trivial inputs don't hit the AI. `detectIntent` is now async; handler catches classifier failures and replies with `intent_classify_failed` (new i18n key, EN + ZH). Also resolves the previously-pending "long-English chitchat → unknown" item (dead code path removed along with the old `isSentenceInput`-based sentence gate). 6 new tests in `tests/unit/ai-text-intent.test.ts`, 11 tests in `tests/unit/telegram-intent.test.ts` (5 new). Mutation kill report (M1–M4) in commit body. Spec: `docs/superpowers/specs/2026-04-20-ai-text-intent-classifier-design.md`.
- [x] **Cloze Span-Wrap (shipped, kept)** — `buildCloze` and four inline cloze sites (`src/app/quick-add/page.tsx`, `src/app/enrich/page.tsx` ×2, `skill/scripts/lib/anki-fields.mjs`) now emit `<span class="nodeword">{{c1::…}}</span>` (outside-wrap) so the Anki template's `.nodeword` CSS rule renders the highlight — applies to every card going forward. Locked by 3 `buildCloze` + 1 `buildSpellingCard` tests in `tests/unit/card-builder.test.ts`. Shipped via PR #1 (`faa2f6d` + `0ff1119`).
- [x] **Long Underlined Phrase Split — built then fully rolled back** — Shipped as `splitLongPhrasesInPages` post-processor in PR #1 (auto-split English ≥5-word underlines into sub-word cards). PR #2 disabled the wiring after photographic evidence from a real worksheet titled "Useful Phrases for Composition Writing" showed every long underline is a legitimate phrase (collocation/idiom). Cloze span-wrap half of PR #1 is independent and kept (see above entry). Net effect vs. pre-PR-#1: only the cloze span-wrap survives. Spec and plan remain at `docs/superpowers/specs/2026-04-19-long-underlined-phrase-split-design.md` and `docs/superpowers/plans/2026-04-19-long-underlined-phrase-split.md` as historical record.
